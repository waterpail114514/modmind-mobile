## Skills 核对

桌面 `workbenchSkillPolicy.ts` 注册 17 类 ModMind 内置领域路由，再按制作模式、会话面和功能包选择适用项；不代表每个用户/项目启用全部 17 类。`resources/codex-skills` 当前这份资源共 48 文件、145480 bytes（约142 KiB），未含用户自定义集合或其他功能包附加资源。

手机 `MobileAi` 没有调用桌面的 `workbenchSkillPrompt` / `workbenchSkillNames` / `syncWorkbenchSkills`，也没有开放 `modmind_user_skills` 的列举/读取工具。打包脚本未复制 `resources/codex-skills` 或工作台功能包 skill 目录。手机目前依靠专用 `developer_instructions` 和项目知识完成任务，不等同领域 skill 路由、按需参考文件读取及验收流程。

| 类别 | 手机状态 |
| --- | --- |
| 模组开发、扩展兼容、构建修复、内容资源 | 领域 skill 正式迁移未完成；相关基础文件/构建工具部分已有 |
| 整合包制作、灵感整理、图像与建模、发布 | 领域 skill 正式迁移未完成；不能把知识笔记、简单模型或图片确认当整套工作流 |
| 游戏/服务器测试、版本迁移、声音等 | 领域 skill 未迁；运行能力缺失或用户已暂缓，不应原封接入后承诺可执行 |
| 用户自定义 Skills | 导入、启用、版本快照、按需读取和管理尚未迁 |

只读检查 OPPO 的本应用 runtime/CODEX_HOME 后，观察到的是 Codex 自带 `.system/imagegen`、`openai-docs`、`plugin-creator`、`review-agent`、`skill-creator`、`skill-installer`；发现的 ModMind 17 类领域 skill 数为 0。通用 CLI 自带 skill 不代表 ModMind 领域迁移，也不证明这些通用 skill 在本应用具备所需工具。

Skills 的这份文本资源体积很小，存储并非主要阻碍；真正要补的是按需发现/读取、两个制作模式的选择、与手机实际 MCP 的对应、权限和验收。优先接可执行的模组开发/构建修复/内容资源、整合包制作和灵感整理，逐项替换或剔除尚不支持的桌面工具引用；其他能力随业务服务迁移。不能只复制文件后标成完整迁移。

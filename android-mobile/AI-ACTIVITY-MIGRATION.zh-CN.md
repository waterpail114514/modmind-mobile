# 手机 AI 过程迁移（2026-11-02）

目标是让工作台、灵感台能解释 AI 正在做什么、结果来自哪次操作，以及停止后还完成了哪些内容。保持只有两个主入口；模组制作和整合包制作共用同一套呈现。

## 实现与复用

沿用项目已经固定的 OpenAI Codex CLI / SDK 0.154.0 和标准 MCP，不新增另一套 AI 引擎、云端开发容器或手机运行依赖。上游为 [openai/codex](https://github.com/openai/codex)，实际协议以仓库已集成版本和手机运行结果为准；没有自动升级 CLI。复用成熟实现可保留工具调用、会话续接和停止语义，新增部分只是 Android 进程传输与移动操作名称适配。

复用桌面 `AgentActivityTracker`、`AiActivity`、`AgentActivityList`、思考内容合并及时间线回放。`AgentReasoningView` 从桌面组件拆出呈现，桌面仍提供原来的 Markdown 渲染，手机提供自己的净化 Markdown 渲染。时间线增加显式的实时回放入口，桌面现有历史入口默认行为保持原样。未引入 Electron 到手机运行包。

原 SDK 的简化事件不足以覆盖所有思考字段，因此手机优先连接内置 Codex 的 app-server 协议；仅在尚未提交模型请求的准备阶段失败时才降级 SDK，提交后失败不会自动重发。本轮标准 MCP 探针返回桌面共用的固定 marker，目录和实际探针都通过后才发起模型请求。

| Before | After | Why |
| --- | --- | --- |
| 只有基础工具文字和最后一条回复 | 操作开始、进度、完成、失败与中断状态原位更新 | 能判断具体操作是否完成 |
| 中途回复缺少稳定身份 | 按 itemId / streamId 回放，中途说明保留，最终正文只显示一次 | 保留解释，不重复正文 |
| 思考文本未接完整协议 | 独立概要/正文，默认折叠，点开查看，内容区有高度上限 | 保持聊天安静，同时可查过程 |
| 文件变更只能找文件菜单 | 活动记录可直接打开对应项目源码，结果卡片保留 | 从结果继续编辑 |
| 后台操作回执易被理解为任务完成 | 活动写“提交…请求”，卡片查询实际后台进度 | 请求完成与构建、检查完成分开 |
| 取消统一使用错误色 | 停止提示用中性色，真正错误保留错误色和重试 | 停止是用户操作，不误报故障 |
| 超过 100 条后依赖手动加载 | 按 100 条自动继续载入，流式结果持续更新 | 长回复不会停在第一批记录 |

模型必须实际返回可展示的思考概要或正文才显示对应内容；不会解密、展示或保存 `encrypted_content`，不根据普通回复编造思考。真实在线验证本轮没有收到思考字段，这不判为故障。

## 容量与权限

流式 delta 每约 160 ms 合并一次，按条目、概要/正文通道和索引分隔，批次最多约 8 Ki 字符；边界事件立即刷出。单轮最多 1000 个持久过程事件、合计约 4 MiB，触及容量主动停止并保留已保存记录。进入发送前沿用约 2000 条会话门槛；前端最多保留 3100 条并按页获取。原生通知待处理容量约 8 MiB，单条 JSON 上限 32 MiB；不积攒无界图片或工具对象。容量不是整机占用的严格上界，底层日志副本和会话元数据仍有成本。

工具仍经过相同会话、项目、参数、版本及只读校验；灵感台不能通过活动点击或模型调用写入项目。内置 shell、任意 apply_patch 和多代理未开放；意外原生权限请求被拒绝。没有复用电脑账号凭据。

## 验证证据

证据位于 `test-results/activity/`，测试项目使用 `qa_activity` 名称，与用户项目分开。

| 检查 | 结果 |
| --- | --- |
| 手机真实 CLI + 本地模型协议夹具 | 原生 app-server → 思考 delta/概要/正文 → MCP 读取/写入 → 持久记录；29 条事件，12 条思考生命周期事件、4 条工具生命周期事件；没有退回 SDK，不消耗在线额度 |
| 取消与续聊 | 实际保持中的模型连接收到取消，任务及时结束，思考与停止记录保留；原生会话 ID 持久化并成功续聊，两轮正文各保留一次 |
| 真实在线模型 | 使用手机已有账号及当前模型，灵感台只读 MCP 读取 README 后返回正文；未改账号/模型、未写项目；本次思考字段数为 0 |
| 映射与回放回归 | `scripts/test-activity.mjs` 8 组通过，含实时文本、概要/正文、去重、中途回复、容量停止和异步任务语义 |
| 桌面共用逻辑回归 | `workbenchTimeline.test.ts` + `agentActivity.test.ts`，48 项通过 |
| 移动业务回归 | 原服务 46 项、完整项目/恢复/检查服务 18 项通过 |
| 严格类型检查 | 真实分类移动端 0；外部 3，均为 `src/shared/soundStudio.ts` 的既有 jfxr 类型诊断；没有把它们算作手机通过项 |

手机 UI 的 `scripts/test-activity-ui.mjs` 使用手机原生事件做回放，并以独立界面夹具验证实时状态。真实在线请求与界面夹具分开记录。浅深主题、两制作模式、两个对话面、44px 折叠与文件触摸跳转、停止后重开、超过 100 条分页及实时正文分别记录在 `ui.json` 和截图中；不能用这些夹具声明所有在线供应商都返回思考。

最终 APK 为 `android/app/build/outputs/apk/debug/app-debug.apk`，281958490 bytes，SHA-256 `498fbc643ee7fa0d9307861b0ae9f8670e867c35f691618587ca0d9edd3da3c3`，运行代码压缩包 442931 bytes；25 个打包资源及 86 个原生组件逐项核对通过。ADB 更新成功，随后强制结束并重开应用，数据保留。`ui.json` 为最终包 360×764 CSS 像素的 6 组交互验证；清理了 4 个本轮多余测试项目条目，保留可回看的样例和真实只读验证对话，未删除用户项目。

APK 仍是调试签名的独立试验版，未发布。游戏实际运行、更多加载器/版本、Git、声音及其余迁移项继续按 `IMPLEMENTATION-20261102.md` 跟踪；本轮过程展示完成不代表它们完成。
